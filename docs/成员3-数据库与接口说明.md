# 成员3：数据库与接口说明文档

> 范围：只写成员3实际负责的数据库对象和后端接口。
> FAQ 和答疑相关接口挂在 `backend/faq/` 目录下，数据库初始化在 `backend/database.py`。
> 当前后端服务端口：8000；独立 AI 网关服务端口：8100。

## 1. 数据库表

数据库为 SQLite，初始化文件是 `backend/schema.sql`，实际运行时再由 `backend/database.py` 做幂等补列。

### 1.1 `faqs`：FAQ 知识库（按组内规范格式）

```sql
CREATE TABLE faqs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    activity_id INTEGER,                    -- 空=全局FAQ,非空=某活动专属
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    category TEXT,                          -- 报名/时间/地点/奖项/综测等
    source TEXT DEFAULT auto,             -- auto(AI自动沉淀)/manual(人工新增)/llm
    status TEXT DEFAULT online,           -- online/offline(下架)
    updated_at TEXT DEFAULT (datetime('now'))
);
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `activity_id` | INTEGER | 空表示全局 FAQ；非空表示某活动专属 |
| `question` | TEXT | 问题，必填 |
| `answer` | TEXT | 答案，必填 |
| `category` | TEXT | 按问题主题划分，例如报名、时间、地点、奖项、综测等 |
| `source` | TEXT | 默认 `auto`；`auto` 为 AI 自动沉淀，`manual` 为人工新增，`llm` 为大模型直接生成 |
| `status` | TEXT | 默认 `online`；`online` 为上线可用，`offline` 为下架 |
| `updated_at` | TEXT | 更新时间，默认当前时间 |

与当前成员3实现的差异（已列入待技术负责人拍板项，文档先按上面规范写）：

| 项 | 当前实现 | 上面规范格式 |
|---|---|---|
| `status` | `published` / `draft` | `online` / `offline` |
| `source` 默认值 | `manual` | `auto` |
| `category` 取值 | 竞赛类、讲座/分享类、培训/工作坊类、招募类、文体活动类、通知类 | 报名、时间、地点、奖项、综测等 |
| `updated_at` | 查询和写入暂未维护该字段 | 有该字段，默认当前时间 |
| `origin_title`、`activity_title` | 实现中有推文溯源和活动标题附带字段 | 上面建表语句没有这两个字段 |

### 1.2 `qa_logs`：答疑日志和高频沉淀依据

由 `backend/database.py` 自动创建，共享 `schema.sql` 中没有这张表：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `activity_id` | INTEGER | 提问时选择的活动，可空 |
| `question` | TEXT | 用户原始问题 |
| `answer` | TEXT | 返回答案 |
| `source` | TEXT | `faq` 命中知识库；`llm` 未命中并走 AI 兜底 |
| `count` | INTEGER | 兼容字段，写入时恒为 1；统计在查询时聚合 |
| `created_at` | TEXT | ISO 8601 秒级时间 |

## 2. FAQ 表格式

### 2.1 分类取值

以组内建表注释为准：

```text
报名
时间
地点
奖项
综测
```

`category` 字段为自由文本，可继续扩展。

### 2.2 状态含义

以组内建表语句为准：

| 状态 | 说明 |
|---|---|
| `online` | 上线可用，默认状态 |
| `offline` | 下架，不对外提供 |

### 2.3 来源含义

以组内建表语句为准：

| 来源 | 说明 |
|---|---|
| `auto` | AI 自动沉淀，默认来源 |
| `manual` | 人工新增 |
| `llm` | 大模型直接生成 |

### 2.4 FAQ 对象示例

```json
{
  "id": 21,
  "activity_id": 2,
  "question": "报名截止什么时候？",
  "answer": "10月20日18:00截止，逾期不补报。",
  "category": "报名",
  "source": "manual",
  "status": "online",
  "updated_at": "2026-10-11 10:00:00"
}
```

AI 提取示例：

```json
{
  "id": 34,
  "activity_id": 2,
  "question": "是否可以跨年级组队？",
  "answer": "可以，3-5人一组。",
  "category": "报名",
  "source": "auto",
  "status": "online",
  "updated_at": "2026-10-11 10:00:00"
}
```

### 2.5 JSON 导入模板

```json
[
  {
    "question": "编程马拉松报名截止什么时候？",
    "answer": "10月20日18:00截止，逾期不补报。",

    "category": "报名",
```

`activity_id` 为 `null` 表示全局 FAQ。

## 3. 后端接口

根路径全部为 `/api`，当前实现直接返回业务对象，没有统一包装。

### 3.1 FAQ 基础 CRUD：`/api/faqs`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/faqs` | FAQ 列表，支持筛选和分页 |
| POST | `/api/faqs` | 新增 FAQ |
| PUT | `/api/faqs/{faq_id}` | 更新 FAQ |
| DELETE | `/api/faqs/{faq_id}` | 删除 FAQ |
| POST | `/api/faqs/from-qa` | 答疑沉淀入口，`source` 强制为 `auto` |

查询参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `activity_id` | int | 按活动 ID 精确筛选 |
| `activity_title` | string | 按活动标题模糊筛选 |
| `keyword` | string | 同时匹配问题和答案 |
| `category` | string | 按六类分类筛选 |
| `status` | string | `published` 或 `draft` |
| `page` | int | 默认 1 |
| `page_size` | int | 默认 20，最大 100 |

列表返回：

```json
{
  "items": [],
  "total": 0
}
```

新增请求：

```json
{
  "activity_id": 2,
  "question": "报名截止什么时候？",
  "answer": "10月20日18:00截止。",
  "category": "竞赛类",
  "source": "manual",
  "status": "published",
  "origin_title": ""
}
```

删除返回：

```json
{"ok": true, "id": 21}
```

错误：

| 状态码 | 说明 |
|---|---|
| 400 | 问题或答案为空 |
| 404 | FAQ 不存在 |

### 3.2 推文 AI 提取：`POST /api/faqs/auto-generate`

| 方法 | 路径 | 调用方 |
|---|---|---|
| POST | `/api/faqs/auto-generate` | 成员2发布推文后调用，或管理员手工粘贴触发 |

请求：

```json
{
  "activity_id": 2,
  "title": "编程马拉松报名启动",
  "content": "推文正文全文",
  "category": "竞赛类"
}
```

行为：

1. 调用独立 AI 网关提取最多 5 条问答。
2. 先删除同一活动的旧 `auto + draft` 草稿，已发布和手工数据不受影响。
3. 写入 `source=auto`、`status=draft`，并把推文标题写入 `origin_title`。
4. 返回本次写入的数据和总数。

返回：

```json
{
  "items": [],
  "total": 3,
  "tip": "已存为草稿(draft)，请管理员审核修改后发布"
}
```

### 3.3 智能答疑：`POST /api/qa/ask`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/qa/ask` | 先查 FAQ，未命中再调 AI 网关 |

请求：

```json
{
  "question": "报名截止什么时候？",
  "activity_id": 2,
  "no_cache": false
}
```

匹配优先级：

1. 已选活动时：先查该活动已发布 FAQ，再查通用已发布 FAQ，不跨其他活动。
2. 未选活动时：在整个已发布知识库中搜索。
3. 仍未命中：调用 AI 网关，记录为 `source=llm`。

返回：

```json
{
  "answer": "10月20日18:00截止。",
  "source": "faq",
  "faq_id": 21
}
```

`source` 为 `faq` 表示命中知识库，为 `llm` 表示 AI 生成。

### 3.4 高频问题候选：`GET /api/qa/candidates`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/qa/candidates` | 找出反复提问但知识库没有的问题 |

查询参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `min_count` | 3 | 最低出现次数 |
| `activity_id` | 空 | 可选，按活动过滤 |

规则：

1. 只统计 `source=llm` 的日志。
2. 归一化后聚合相同问题。
3. 开启真实网关时再做 AI 同义合并。
4. 已存在于 FAQ 的问题不再返回。

返回：

```json
{
  "items": [
    {
      "question": "食堂几点开门",
      "answer": "AI 原答案",
      "activity_id": null,
      "count": 3
    }
  ],
  "total": 1,
  "min_count": 3
}
```

### 3.5 高频问题接受：`POST /api/qa/candidates/accept`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/qa/candidates/accept` | 把高频候选转成待审核 FAQ |

请求：

```json
{
  "activity_id": null,
  "question": "食堂几点开门？",
  "answer": "以学校官方通知为准。",
  "category": "通知类"
}
```

写入固定为：

```text
source=auto
status=draft
origin_title=高频提问
```

### 3.6 问答反馈：`POST /api/qa/feedback`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/qa/feedback` | 赞和踩 |

请求：

```json
{
  "faq_id": 21,
  "action": "dislike",
  "question": "报名截止什么时候？"
}
```

行为：

- `action=like`：仅记录前端状态，不更新 FAQ。
- `action=dislike` 且有 `faq_id`：把对应 FAQ 状态改为 `draft`，等待重新审核。
- 纯 AI 答案没有 `faq_id`：只做用户反馈提示，不更新知识库。

返回：

```json
{
  "ok": true,
  "faq_downgraded": true
}
```

## 5. 变更申请表

影响范围：`faqs` 表写入和返回字段；`qa_logs` 为新增配套日志表

### 5.1 当前 SQL 表格式

```sql
CREATE TABLE faqs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    activity_id INTEGER,                    -- 空=全局FAQ,非空=某活动专属
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    category TEXT,                          -- 报名/时间/地点/奖项/综测等
    source TEXT DEFAULT auto,             -- auto(AI自动沉淀)/manual(人工新增)/llm
    status TEXT DEFAULT online,           -- online/offline(下架)
    updated_at TEXT DEFAULT (datetime('now'))
);
```

```sql
CREATE TABLE qa_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    activity_id INTEGER,
    question TEXT NOT NULL,
    answer TEXT,
    source TEXT,
    count INTEGER DEFAULT 1,
    created_at TEXT
);
```

### 5.2 要求变更的点

| 编号 | 变更对象 | 当前组内规范 | 申请变更为 | 原因 |
|---|---|---|---|---|
| 1 | `faqs.status` | `online` / `offline` | `published` / `draft` | 现有审核流程需要待审核状态：AI 提取、高频沉淀、用户踩降级后都要先进入 `draft`，人工审核后再发布；`offline` 只有下架语义，无法表达待审核 |
| 2 | `faqs.source` 默认值 | `auto` | `manual` | 管理员手工新增是主要写入入口；默认 `auto` 会把人工数据误标为 AI 沉淀，影响统计口径 |
| 3 | `faqs.category` 取值 | 报名、时间、地点、奖项、综测等 | 竞赛类、讲座/分享类、培训/工作坊类、招募类、文体活动类、通知类 | 现有 FAQ 页面按活动类型筛选和管理；若改成问题主题，现有筛选、示例数据和前端下拉都要返工 |
| 4 | `faqs.origin_title` | 规范中没有该字段 | 新增 `origin_title TEXT DEFAULT ''` | 推文 AI 提取必须记录来源推文标题，否则同一活动的多篇推文无法区分来源 |
| 5 | `qa_logs` 整表 | 共享 schema 中没有该表 | 新增配套日志表，见上面建表语句 | 高频问题沉淀依赖答疑日志统计；该表只写日志，不改共享业务表 |

### 5.3 已按规范完成、无需变更

- 已新增并维护 `faqs.updated_at`，新增和更新接口都会写入当前时间。
- `activity_title` 仍为查询附带字段，不是物理列。
- `qa_logs.created_at` 使用 ISO 8601 时间。

## 6. 独立 AI 网关接口

成员3后端通过 HTTP 调用网关，默认地址为 `http://127.0.0.1:8100`。

| 用途 | 接口 | 说明 |
|---|---|---|
| 智能答疑兜底 | `POST /api/ai/chat` | 请求含问题和可选活动 ID |
| 推文关键问题提取 | `POST /api/ai/extract-faq` | 请求含标题、正文和数量 |
| 高频问题同义匹配 | `POST /api/ai/similar-question` | 返回最相似候选下标 |

网关不可用或者未开启真实模型时，成员3后端自动使用本地 Mock，不影响业务流程。
